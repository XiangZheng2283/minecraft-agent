- **修复**：逐个尝试候选位置并重新检查目标方块；服务器拒绝时有限次转到下一位置，成功后才写世界记录。避免在同一次动作里无限重试。
- **回归与审查**：覆盖背包物品消失、目标方块变化、全位置失败和相同坐标反复重试。

### S12 · P2 · 共享经验跨 bot 可召回

- **证据**：`bot/models.mjs:24` 和 `README.md:123-127` 描述“所有 bot 的经验”；`bot/agent.mjs:30-34` 调用 `knowledge.search(query,{bot:config.name})`；`bot/knowledge.mjs:173-177` 排除其他 bot 的记录。已用真实 `openKnowledge({path:':memory:'})` 复现：miner 写入经验后，不过滤时命中 1 条，以 helper 查询时命中 0 条。
- **红测试**：bot A 写入 `source:experience` 后 bot B 的 `recall_experience` 可查；个人 `search_notes` 仍只查自身 world；全局配方/策略结果不退化。
- **修复**：共享经验查询不按当前 bot 过滤，保留 `bot` 字段作来源标记；若存在不应公开的记录，先显式分类并只共享允许的经验，不直接扩大私有 owner 备注。
- **回归与审查**：核对检索排序、来源标识和数据边界；涉及跨 bot 可见性，需额外审查信息暴露范围。

### S13 · P1 · “交给主人”必须有独立完成条件（待验证）

- **证据**：`bot/skills.mjs:147-149` 的 `owner_give` 调用 `toss`；`bot/agent.mjs:121-132` 只看 bot 自身库存是否达到 targets，不能证明主人实际收到。这里是交付语义风险，**尚无真实领取失败复现**。
- **红测试**：仅库存达标不得将“交付”请求宣布完成；仅 `toss` Promise 成功也不得假称主人已收到；可观察的主人领取/明确确认后才记录 delivered。主人离线、超距、物品落地时保留未完成或需确认状态。
- **修复**：将收集目标与交付后置条件分开；若 Mineflayer 不能可靠观察主人背包，回复“已投递/待确认”，由明确的领取事件或主人确认推进完成，不伪称已送达。
- **回归与审查**：覆盖收集后交付、部分交付、新请求中断、主人改名/不在线；与 S03、S05 的目标版本绑定。

### S14 · P1 · 长动作超时与取消契约（待验证）

- **证据**：`bot/skills.mjs:39-47` 的 `bounded` 通过 `Promise.race` 超时；`bot/skills.mjs:139,149,177,194-204` 等动作含等待或外部操作。`pause()`/`stop()` 是否取消已启动的各类动作尚未逐项实测，本项为**补充验收风险**。
- **红测试**：模拟永不返回的寻路、睡眠、容器操作和模型等待；超时或 pause/stop 后没有新的副作用、目标与控制状态可收敛；恢复时不会由旧 Promise 写入旧结果。
- **修复**：为长动作明确可取消边界、清理职责和统一超时；无法取消的服务端操作须把后续回调视为过期结果，避免旧动作污染新请求。
- **回归与审查**：逐动作检查定时器清理、资源关闭和重复执行安全性；不以 `Promise.race` 返回本身证明底层操作已停止。
